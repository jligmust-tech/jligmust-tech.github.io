Contribute public research records

Help extend the research router with new studies, benchmark resources, and reproducible result records.

Public contributions only — the site does not run models. Do not attach private databases, proprietary downloads, credentials, model weights, or raw execution dumps; concise source-linked result summaries are welcome.

Submission routes

Use a GitHub issue for guided review, or download a CSV template for a planned pull request.

Submit a new study → Submit a result → Study CSV template Result CSV template

Issue submissions are discussion records. A maintainer adds accepted records to the versioned CSV only after the public-source and protocol checks below.

Time-aware status model

Publication status answers “what is publicly released?” Evidence status answers “how much has this site checked?” They must not be collapsed.

FieldMeaningRequired timestamp rule
publication_statusUnpublished, preprint, under review, published, or public release.Do not infer publication from a repository update.
evidence_statusSubmitted, public-source verified, protocol-comparable, needs clarification, not comparable, or accepted.Every change updates status_updated_at.
submitted_atWhen the contributor sent the record.Set once; retain the original submission time.
status_updated_atWhen the current status was last checked or changed.Required for every record, including unpublished records.
published_atWhen a publication or formal public release exists.Leave blank while unpublished or under review.
last_verified_atWhen the linked public source was last checked.Update when links, versions, or artifacts are rechecked.

Example: Unpublished · status checked 2026-09-08 means the item is publicly submitted but has no publication date. It is not treated as published evidence. Status changes are retained in the public status-history export.

New study or benchmark fields

Use study_submissions.csv or the new-study issue template.

Provide the study name and type, publication and evidence statuses, all required timestamps, public paper/repository/dataset URLs, task definition, holdout or split, metrics, baselines, and a short contributor note. A preprint, public repository, challenge page, or public dataset landing page can be valid public evidence even when no peer-reviewed publication exists.

Benchmark result fields

Use result_submissions.csv or the result-submission issue template.

Provide the model and version/commit, dataset or suite, exact split, endpoint, metric and score, uncertainty or repeat count, baseline, pretraining-overlap disclosure, public code/configuration URL, source URL, license note, and all status timestamps. Scores remain separate from the official leaderboard until the dataset, split, metric, baseline, and source are comparable.

Review checklist

Maintainers should be able to audit a contribution without requesting private files.

  1. Confirm that every evidence link is public, stable enough to cite, and relevant to the claim.
  2. Check publication status independently from repository or preprint activity; record status_updated_at.
  3. Check that dataset, holdout, endpoint, metric, baseline, and model version are explicit.
  4. Check pretraining/test overlap and mark unknown disclosure as unknown rather than assuming no overlap.
  5. Keep source-reported, community-submitted, protocol-comparable, and verified records visibly distinct.
  6. Reject private data, proprietary downloads, credentials, unverifiable scores, and claims that require running a model.

Data policy

The contribution layer extends the public research map; it does not become a raw-data repository.

Accepted records contain metadata, links, citations, and contributor-provided summaries or scores. They do not contain downloaded datasets, private database exports, model weights, access tokens, or executable jobs. Community submissions are versioned through public GitHub history and remain clearly labeled in the site’s tables and future plots.
